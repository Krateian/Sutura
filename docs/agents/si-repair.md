# Si Repair

Trigger: Self-intersection: Autorefine, SI excise/re-cap, local exact, SI mode.

Source: `origin/main:AGENTS.md` @ 5e28b78, ranges 57-58, 65-66, 73-73.

- `sutura/autorefine.py` (numpy + sutura_geom only, no pymeshlab/scipy/trimesh) is the experimental self-intersection resolution prototype (FAZ16) behind `--experimental-autorefine` (CLI + GUI batch-wide checkbox `chk_autorefine`): a from-scratch reimplementation of the Lazard & Valque 2025 loop — identify properly-intersecting triangle pairs (broad-phase grid hash + vectorized float64 prefilter + adaptive Shewchuk-style `orient3d`), snap-round the involved vertices and their cell-mates onto a float-exact grid, subdivide each triangle along its intersection segments (conforming: split points propagate to every triangle sharing the edge), round new vertices to the grid, iterate <=5 times with a faces-growth cap and a no-progress early stop. **It NEVER deletes an input face** (each triangle is kept or split), the property that targets the documented "extreme mode can worsen heavy-SI scans" failure mode. In `repair_mesh_from_arrays` the flag re-runs the same stage-1 chain on the autorefine-preprocessed input and **adopts it only when the final output has holes and non-manifold edges no worse than the baseline chain** (adopt/fallback guard); the report carries `experimental_autorefine` (si_before/si_after/iterations/converged/capped/adopted; `--human` shows an "Autorefine (experiment)" line). Exact predicates come from `sutura_geom.orient3d` (the Rust `robust` crate, Shewchuk adaptive-precision arithmetic); do NOT use the 2D-only `robust`/`shewchuk` packages. Measured on the 8 real-world SI targets: clear win on moderate-SI meshes (thingi10k_1038439 SI 411→97 standalone, 532→123 integrated vs chain-only; thingi10k_46012 224→168 integrated), NOT a win on dense-SI scans (1038441, metal-nut, 100281) where the float64 construction opens holes the chain cannot fully re-close — the documented EPICK limitation, which is why it stays flag-gated. `benchmark_repair_corpus.py` now records input/output SI (`input_self_intersections`/`output_self_intersections`/`stage1_si_remaining`) but the strict watertight metric deliberately still excludes SI. Keep `autorefine.py` in the module lists of `install.sh`, `install-macos.sh` and `scripts/build_appimage.sh`. The feasibility report and full before/after numbers are in `docs/alpha-wrap-feasibility-2026-09.md`.
- **FAZ16 refinement — iterative snap-rounding pass:** `autorefine.py`'s base loop gained the CGAL 6.1 (June 2025) second-half fix. After each snap, `_eliminate_degenerate` removes the degenerate/sliver/duplicate faces that snapping creates (never a whole non-degenerate input triangle), and `_iterative_snap_round` re-snaps + re-resolves the still-intersecting vertices iteratively (bounded by `MAX_SNAP_ROUNDS=8`, strict-decrease guard). The grid stays at the FINEST float-exact level (2^23) — coarsening it was measured on the heavy-SI corpus and rejected (100281: fine grid 906→97 pairs vs coarsened 906→74289; coarse grids amplify cell-mate snapping and manufacture new intersections). The report gained `snap_rounds_per_iteration`/`grid_scales_used`. Standalone pymeshlab-SI vs the pre-refinement autorefine: 100281 3677→4849→3787, 1038439 411→97→69, 46012 454→466→214. Same flag, same adopt/fallback guard.

- **Guarded Stage-1 self-intersection excise + re-cap (`repair.si_excise_recap`, Full Mend).** After the stage-1 chain (+ delete-fallback + join), `repair_mesh_from_arrays` runs a guarded SI excision only when `deep_repair == 'full'` and `mode != 'extreme'` (extreme keeps its legacy `extreme_extra_passes`). It selects the self-intersecting faces with the exact Rust classifier, dilates one ring, deletes them, drops unreferenced vertices, repairs non-manifold edges/vertices and re-caps with the native `topology.close_holes(self_intersection=True)` (VCGLib-compatible ear clipping; the former Liepa refinement was removed because it changed no excise outcome). A round is committed only when `si_after < si_before` AND `holes_after <= holes_before` AND `nm_after <= nm_before`, where the hole metric is `get_topological_measures['boundary_edges']` (NOT `number_holes`, which reported `-1` on thingi10k_145065 because of its non-manifold vertices and wrongly accepted a round that opened 42 boundary loops); otherwise the pre-round `(verts, tris)` arrays are restored byte-for-byte. The connected-component removal filter is never called (no component is dropped). Bounds: at most `SI_EXCISE_MAX_ROUNDS=3` rounds and a `SI_EXCISE_MAX_FACE_FRACTION=0.30` scope brake; the round count and the brake bound the work, and elapsed time is only reported. A non-positive preset budget (`SI_EXCISE_BUDGET_BY_INTENSITY`: quick 0 s) still disables the pass; `budget_s` remains in the report. The report key `si_excise` (ran/applied/rounds/initial_si/si_after/removed_si/reason/budget_s/seconds/history) is attached ONLY when a round was accepted, so any mesh the excision cannot improve — including every 0-SI mesh — keeps the pre-existing report and output byte-identical (this is what keeps `deep_repair=None` vs `'full'` unchanged on the deep-repair regression fixture). Env opt-out `SUTURA_SI_EXCISE=0` (no CLI/GUI flag; documented in `docs/cli-gui-parity-notes.md`). The former `SUTURA_REFINE_HOLE=1` Stage-1 hole-fill refinement switch was REMOVED in Phase 4 W3d (it was OFF by default and measured to worsen an open mesh — thingi10k_100827: 9 → 23 holes, SI 29 → 77 — so the plain native closer is always used). Regression `tests/test_si_excise.py`.
- **Localized exact self-union of residual SI clusters (`sutura/local_exact.py`, experimental, OFF by default).** After Stage 2 + P-WELD a mesh can still carry residual proper self-intersections (manifold3d accepts intra-shell folds as long as every edge has two faces). This tier detects the SI faces (exact Rust classifier ≤ `SI_MAX_FACES`; above the cap the count is unknown, with no PyMeshLab fallback), partitions them into edge-connected clusters, dilates each by `LOCAL_EXACT_K_RINGS=2` vertex rings (merged disjoint, `LOCAL_EXACT_MAX_PATCH_FACES=2000` brake), runs `sutura_geom.arrangement_lite` on the patch and keeps the facets on the outer hull of the WHOLE mesh (winding queried against one `sutura_geom.PyMeshBvh` built over every face), verifies the patch's directed boundary is bit-identical to the input and its own SI is zero, stitches, and keeps a cluster only when the reload-honest `(holes, non_manifold)` count does not rise (else byte-identical rollback); budget `LOCAL_EXACT_BUDGET_BY_INTENSITY` (quick 0/balanced 10/thorough 45/extreme 120 s). It is OFF for every install, opt-in `SUTURA_LOCAL_EXACT=1` (no CLI/GUI control by design; parity documented in `docs/cli-gui-parity-notes.md`), and a byte-identical no-op when disabled, SI-free, or unaccepted. **Negative result (measured 2026-09):** on the 40-mesh corpus (12 meshes with residual SI) it changes one mesh only (`thingi10k_63785`, Stage-2 SI 81→75; strict 135→125) and on the private `ornate-frame` fold accepts 1/80 clusters (6014→6010) because the fold is whole-shell, not local (97 % `boundary_split`); the plan's locality assumption does not hold, so the real fix is global snap-rounding in the Rust core. Code, `PyMeshBvh`/`winding_points_par` and `tests/test_local_exact.py` are kept; full numbers in `docs/local-exact-notes.md`. `local_exact.py` must stay in the module lists of `install.sh`, `install-macos.sh`, `scripts/build_appimage.sh`, `sutura/updater.py` and `build-macos.yml`.

- **Self-intersection policy (`repair.resolve_si_mode`, `--si-mode`).** Mode in `SI_MODES = ('repair','report','off')`, default `SI_MODE_DEFAULT='report'`, env `SUTURA_SI_MODE`; precedence CLI > env > default (invalid env falls back to default, invalid CLI is rejected by argparse). `report` (default): the stage-1 residual SI count is still measured and reported (`stage1.self_intersections_remaining`, and validate/dry-run `self_intersections`) but SI alone no longer escalates the deep-repair ladder nor fails a result — `repair._dressing_wanted` only lets a positive SI count trigger the automatic Dressing fallback under `'repair'`, and validate's watertight predicate accepts `self_intersections in (0, None)`. `off`: the exact Rust classifier is skipped, the count is reported as `None` ("not measured"). Explicit force flags (`--experimental-dressing`, `--experimental-fallback-ftetwild`) override the policy and still act on residual SI (`_dressing_wanted(True, ...)` always runs; fTetWild's force trigger is unchanged). `repair.si_excise_recap` keeps its own independent count in every mode. The chosen mode is threaded through `repair_mesh_from_arrays` (`stats['si_mode']`), `deep_repair_ladder` (`deep_repair.si_mode`, `_dressing_damage(measure_si=...)`), `repair_file`/`repair_3mf`/`process_file`, `validate_file`/`validate_mesh_from_arrays` and `dry_run_file`/`dry_run_mesh_from_arrays`; the CLI flag sits after `--deep-repair` and the GUI exposes it as the Options → Repair `cmb_si_mode` combo (*Report only / Repair / Do not measure*) which adds `--si-mode` only when it differs from the default. Regression `tests/test_dressing.py::test_resolve_si_mode` / `test_dressing_trigger_si_only` and `tests/test_methods_gui.py` (SI-mode flag + combo mapping).
