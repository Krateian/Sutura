# Diagnosis Classifier

Trigger: Classification, confidence, health/defects, mesh classifier, learning triage.

Source: `origin/main:AGENTS.md` @ 5e28b78, ranges 45-48, 55-56, 131-144.

- Result classification lives in `sutura/classification.py` (stdlib-only, no numpy/pymeshlab): `classify()` returns `(category, issues, summary_key)` and both the CLI (`repair.py`) and the GUI (`gui.py`) import it so they never diverge. "Watertight" is only claimed when stage 2 actually ran and returned `ok`; a stage-1-closed mesh with stage 2 skipped/errored/never-run (e.g. macOS in-process fallback unavailable) is a warning. CLI `--human`/JSON label issues via this module (English, not localized); the GUI localizes the same codes through its EN/TR dictionary.
- `sutura/confidence.py` (stdlib-only) computes the repair confidence score: `repair_confidence()` (post-repair, category-anchored, stage 2 dominant, hard errors forced to 0/low) and `estimate_confidence_pre_repair()` (validate / `--dry-run` estimate, missing signals ignored). It lazy-imports the tuning gates from `repair.py` (`MECH_TUNE_GATE`/`ORG_TUNE_GATE`) so the score can never drift from the real repair thresholds; shared by the CLI and the GUI.
- `sutura/sutura_engine/health.py` (stdlib-only leaf module, P0 error isolation) is the single central wrapper for every tier/method run: `tier_guard(method, stage)` (a context manager that catches a tier body, records a structured `MethodError {method, stage, kind, message}` via `record_error`, swallows it — `KeyboardInterrupt`/`SystemExit` always propagate — and exposes `.error` for the caller's existing fallback), `guard(...)` for a single risky call, and `check_availability()/check_availability_detail()` as the ONE availability checker (`Status` OK/SKIP/FAIL; a missing optional addon such as fTetWild is SKIP, not FAIL). `check_required_geometry()` is the ONE central check for the mandatory `sutura_geom` Rust extension: it verifies the module imports AND exposes the no-fallback symbols `flap_fill`, `morph_close` and `tamponade` (`GEOM_SYMBOL_MISSING_MESSAGE` for a stale wheel), `require_geometry()` raises the named `GeometryRequiredError`, and `check_availability_detail` marks every method FAIL (never SKIP) when it fails. The check is used by the CLI startup gate (exit 1 with a named JSON/plain error before any mesh work, while `--help`/`--version`/informational subcommands still work), by the narrowest shared library entry `repair_mesh_from_arrays` (so direct `repair_file`/`process_file`/method API calls cannot silently degrade), by `RepairMethod.available()` (so `--list-methods`, `methods_json()` and the GUI *Use method* menu agree with `--self-check`), by `--self-check` (0/19, exit 1) and by the GUI startup banner. `sutura_geom` is deliberately NOT in `OPTIONAL_IMPORT_MODULES`, so a tier ImportError for it is recorded as an error; the Flap dispatcher raises the named `FlapUnavailableError` rather than falling back. It is imported by `repair.py` and `sutura_engine/triage.py`; because it is a leaf it does not create an import cycle (the lazy `triage._repair_mod()` stays). Every tier in `repair_mesh_from_arrays`/`deep_repair_ladder` (apply_chain filters, flap/closing/tamponade/graft/dressing/wall/repeat/local-remesh/fTetWild/engines/debris, autorefine, indirect autorefine, shell-analyze, outer-shell, si-excise) and `triage._attempt`/`_auto_multi` route their exception through it; the Flap/Tamponade final safety nets, `p_weld_final`, `process_file` and the optional score block are deliberately NOT routed (documented in the module docstring). `process_file` opens a per-file scope, attaches `result['method_health']` (availability overlaid with the run's errors: `{total, ok, failed, skipped, methods, errors}`), and `--human` prints a `Methods: N/19 OK (X failed, Y skipped)` line beside the existing mesh-quality `Health:` line; the GUI repair log shows the same (EN/TR `repair_log_methods*`). `SUTURA_METHOD_HEALTH=0` disables RECORDING only — the parity switch `tests/test_method_health.py` uses to prove the wrapper never changes a repair result (output bytes and report minus the new keys). The engine package is copied wholesale, so the new module needs no `APP_MODULES` / install-list edit. `stats['method_errors']` is attached to every `repair_mesh_from_arrays` report (always present, empty when clean).
- `sutura/defects.py` (stdlib+numpy only) detects the input mesh's holes and non-manifold regions from plain `verts`/`tris` arrays; `repair.py` calls `detect()` on the input and stores it in the report's `defects` key (always in JSON; `--human` only with `--defects`). The GUI renders the selected file's defects in a panel below the log. Keep it free of pymeshlab/trimesh so it stays importable anywhere. `detect(..., with_indices=True)` additionally returns each defect's `verts_idx`/`faces_idx` index lists for the heatmap; the CLI uses the default (False) so its JSON contract is unchanged.

- `sutura/mesh_classifier.py` (stdlib+numpy only) heuristically classifies a mesh as `mechanical`/`organic`/`unknown` from dihedral-angle geometry. Its confidence is a **signed-margin score**: sigmoid memberships over three corrected dihedral bands (near90 `[60,120]°`, true-flat `<1°`, gentle-curvature `[1,15)°`; mechanical = max/OR of near90 & flat signals, organic = min/AND of low near90, low flat, high gentle), decisions at fixed floors (`mechanical >= 0.7`, `organic >= 0.5`), and `unknown` carries a non-zero proximity value + `metrics['leaning']` instead of a flat 0. NOTE: the edge→face pairing uses `i % F` (the concatenated edge array is block-stacked, not per-face); the old `i // 3` paired up unrelated faces and produced garbage near90/coplanar — the old `coplanar` metric was replaced by the `flat`/`gentle` split precisely so smooth high-poly organics (dihedrals ~2-5°, i.e. `gentle`) never read mechanical. `repair_mesh_from_arrays` calls it and, on non-`unknown`, tunes two Stage 1 thresholds (`mincomponentsize`, `maxholesize`) via the module-level `_TYPE_PARAMS` table in `repair.py` — but only when confidence clears the **class-specific tuning gate** (`repair.MECH_TUNE_GATE=0.75`, `repair.ORG_TUNE_GATE=0.70`, helper `repair.tuning_applied_for`): below the gate the detected type is still reported but the conservative default thresholds are used, and the report carries `tuning_applied` (true/false; shown in `--human` and the GUI defect panel). Both gates sit just above the worst correct prediction on the corrected set (mechanical min 0.867, organic min 0.693) — the old `0.55` organic gate and its "structurally capped at ~0.62" rationale were artifacts of the pairing bug. Those per-type values are EXPERIMENTAL/uncalibrated starting points (see the code comment) — treat them as reversible. The result lands in the report as `detected_type`/`detected_confidence` and is shown in the GUI defect-panel header. Keep it free of pymeshlab/trimesh. Threshold resolution for BOTH the real repair and `--dry-run` goes through `repair.resolve_mode_params(mode, type, conf)` (returns `(params, tuning_applied)`), so they can never diverge.
- **Classifier engine selection (`repair.resolve_classifier_engine`).** The DEFAULT engine is `experimental` — `sutura/mesh_classifier_v2.py` (RANSAC plane features + a curvature developability signal + a trained numpy logistic head). Measured on the 40-mesh real-world corpus (36 labeled): experimental 29/36 vs classic 16/36 (mechanical recall 16/20 vs 2/20; organic 13/16 vs 14/16); LOO-CV on the 71-mesh labeled set (35 synthetic + 36 real) is 0.845 vs classic 0.648. The developability signal (`developable_fraction`, the area fraction whose normals lie on a common great circle) is what lets the head classify curved-but-mechanical parts (cylinders, tubes, fillets) that classic reads as `unknown`; the synthetic set gained `cylinder_*`, `tube_*`, `fillet_bracket` + damaged variants (now 35 meshes). `classic` (`mesh_classifier`) remains selectable via `--classifier-engine classic` / `SUTURA_CLASSIFIER_ENGINE=classic`. Precedence: CLI flag > env var > default (`experimental`); an invalid ENV value falls back to the default, an invalid CLI value is rejected by argparse. `repair.classify_with_engine` runs the selected engine and, on an exception/invalid result from `experimental`, SILENTLY falls back to classic with a stderr warning (never a crash) — `repair_mesh_from_arrays` reports the engine actually used as `classifier_engine`. **Near-boundary classic-agreement fallback (FAZ4):** the head's confidence is the margin from its 0.50 decision boundary, so `p_mech` near 0.5 is "no opinion" — the FAZ2-retrained head sat artec_metal-nut at p_mech=0.489 (conf 0.022, below ORG_TUNE_GATE), silently disabling organic tuning and dropping the 115-mesh corpus from 103 to 102 watertight. When `|p_mech - 0.5| * 2 < repair._HEAD_MARGIN` (0.15) AND classic strongly agrees with the barely-chosen class (`_classic_verdict` class == head class, classic class-score >= 0.70), the head keeps its class but reports classic's confidence, so the tuning gate sees the strong agreeing signal. Confident head decisions are NEVER overridden (no classic veto — that was tried and reverted as counterproductive). On the 115-mesh corpus this fallback fires on exactly ONE mesh (metal-nut); the near-boundary DISAGREEMENT cases (head coin-flip, classic strongly opposite: crankshaft, motorcycle-engine-cover-hd, plaster-cast-teeth) keep their low confidence → no tuning → conservative defaults, which is the intended "lean conservative" behaviour. **Eigenvalue shape descriptors evaluated, NOT integrated (FAZ6):** the Weinmann/Jutzi/Mallet (2015) point-set eigenvalue descriptors (Linearity/Planarity/Sphericity/Omnivariance/Anisotropy/Eigentropy/Surface Variation from the vertex-position 3x3 covariance) were implemented from the formulas in numpy and tested as extra head features. LOO-CV on the 71 labeled set gets WORSE (0.845 -> 0.831 with +linearity+sphericity, 0.817 with all 7; robust across floors 0.50-0.65): mechanical recall gains at most 1 while organic loses 2 — the global eigenvalue shape is largely redundant with the existing curvature/planarity features, so it was NOT integrated (the classifier is unchanged). **Local roughness/geometrical/statistical features as a tie-breaker, NOT integrated (FAZ8):** the IvanNik17 repo was re-read in full (roughness: GC roughness Wang 2012, DON Ioannou 2012, density Rabbani 2006, intensity entropy N/A for STL; geometrical: density/farthest/max-height/height-std Blomley-Weinmann 2016; statistical: D1-D4/A3) and reimplemented from scratch (1-ring vertex neighborhood, pure numpy); timzhang642/3D-Machine-Learning re-checked and confirmed as a link list, no code. Tested NOT as feature fusion but as a tie-breaker on the boundary/disagreement subset only (head conf < 0.5 or real-class disagreement): baseline 0.778 (27 meshes) -> 0.741, refined 0.643 (14) -> 0.429, per-feature |r| <= 0.36. Does not help, so NO --experimental-tiebreaker-features flag / GUI toggle was added and the classifier is unchanged. The source repo the ideas came from is GPL-3.0 (incompatible with Sutura's PolyForm Noncommercial license), so no code was copied — only the public formulas; the README "Classifier methodology" section documents the attribution and both negative results. Do not re-introduce these features without new evidence. **MeshCNN 5-D edge features evaluated as fusion AND tie-breaker, NOT integrated (FAZ9):** the MeshCNN per-edge feature (Hanoeka et al. 2019, MIT — reimplemented cleanly from the formula in numpy, no code copied) was implemented: for each interior edge, `dihedral = pi - arccos(n1.n2)`, sorted `symmetric_opposite_angles` (apex angle opposite the edge in each triangle) and sorted `symmetric_ratios` (apex-height/edge-length per triangle); 5 per-edge values -> 10 global mean/std stats (verified: cube dihedral mean ~2.09, smooth sphere ~2.97). Test A (fusion, LOO-CV on 71 labeled): base 0.845 -> base+10 edge features 0.831 (WORSE). Test B (tie-breaker on the FAZ8 boundary subset): union n=27 baseline 0.778 -> 0.741 (LOO, worse); refined n=14 baseline 0.643 -> 0.857 (LOO) but 3-fold x20 repeats give all-10 0.733 / best-3 0.902 — n=14 too small for "clear" evidence, best-3 has selection bias, union shows no help. Not a robust win -> NOT integrated (no --experimental-edge-features flag, no GUI toggle). NOTE the block-stacked edge indexing trap: the concatenated per-face edge array is [all (0,1) edges, then all (1,2), then all (2,0)] — use concatenate([arange(F),arange(F),arange(F)]) for edge->face, NOT repeat(arange(F),3) (same trap as mesh_classifier's i % F pairing). **Retrospective single-feature scan (FAZ10, project standing rule):** per-feature |correlation with the label| was computed on the FULL 71-set for all three rejected families — the top signals are REAL and above the n=71 noise bar (|r| < 0.4): `oppmax_std` (MeshCNN ratio-max std) r=+0.718, `don_mean` (DON) r=+0.673, `dihed_mean` (MeshCNN) r=-0.633, `rmin_mean` r=+0.563, `gc_mean` r=+0.480 — all sign-stable across 30 bootstrap subsamples (std ~0.04). However, added as a SINGLE feature the standalone LOO/5-fold-CV gain is marginal (<=+0.007 mean accuracy; deterministic LOO 0.845 -> 0.859 = 1 mesh; NO verdict flips in a final-model fit) — these strong correlates are largely REDUNDANT with the existing dihedral-based features (near90/flat/gentle + developable). None cleared the very-high standalone-integration bar; flagged as "interesting sub-pieces, revisit only via a proper feature-selection framework or with new data", NOT integrated. Standing rule: ALWAYS report per-feature |r| for rejected experiments, and flag any single feature with |r| > 0.4 that is consistent (full-set + bootstrap) for a separate standalone mini-evaluation. **Manifold cross-validation layer (FAZ10):** `sutura_geom.watertight_check(verts, tris)` gives an independent Manifold verdict (constructs with NoError and is non-empty => watertight). It sits NEXT TO defects.detect() strict watertight and never replaces it; integrated as an extra reporting column in `scripts/benchmark_repair_corpus.py` (`manifold_watertight`/`manifold_status`/`manifold_consistent`). Regression-tested by `tests/test_manifold_watertight.py`. **Opt-in edge-tiebreak head (FAZ11, `--experimental-edge-tiebreak`):** the five strongest FAZ10 scan signals (oppmax_std, don_mean, dihed_mean, rmin_mean, gc_mean) are NOT added to the default vector (LOO flips ~1 mesh, redundant with dihedral features). They are available as an OPT-IN 11-feature head (`V2_EXTRA_*` weights, `classify_mesh(extra_features=True)`, CLI flag threaded through `classify_with_engine`/`repair_mesh_from_arrays`/`process_file`; GUI batch-wide checkbox `chk_edge_tiebreak`). Trained on the 71 labeled set (LOO 0.845, 5-fold x20 0.852 vs base 0.850). **GUI FAZ11 features:** the interactive viewer gained a "defect colours" mode (red=non-manifold, orange=flipped, yellow=degenerate via `defects.defect_type_colors` -> npz `defect_colors` -> `heatmap.prepare_render(face_colors=...)`), and the main window gained a "What changed" repair-log panel (`_render_repair_log`, `_repair_log_by_path`). `mesh_classifier_v2.py` must stay in the module lists of `install.sh`, `install-macos.sh` and `scripts/build_appimage.sh` (it is imported only inside the experimental branch, so a missing file silently degrades every install to classic). The calibration harness `scripts/calibrate_classifier.py` defaults to `experimental` too.

- **Learning triage (`sutura_engine/learning.py` + `methods.rank_methods`,
  v0.6.1).**
  `sutura_engine.learning.record_learning` (re-exported as
  `history.record_learning`) aggregates the anonymous per-repair
  `methods_tried` entries (id, template, outcome, elapsed_ms added by
  `triage._record`) into `~/.local/share/sutura/data/triage_learning.json`
  (override with `SUTURA_DATA_DIR`; privacy rule unchanged: template ids +
  method slugs only, never a file/name).
  `history.learning_bonus` is a Beta(2,2) posterior success mean scaled to
  `[0, LEARNING_MAX_BONUS=0.05]`, damped by a speed factor, zero without data;
  `rank_methods` adds the max bonus over the templates the analysis actually
  fired (never invents a score for an un-favoured method). Toggle: config
  `learning_triage` / `SUTURA_LEARNING_TRIAGE` / CLI `--no-learning-triage`;
  reset: CLI `clear-learning` and GUI Options → General → Reset learning.
