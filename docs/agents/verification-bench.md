## Verification tiers

Repair-path work is gated by the tiers in
`.claude/skills/sutura-verify/SKILL.md` (the canonical metric/mode rules).
Summary:

| Tier | When | Scope |
|---|---|---|
| T0 | every commit | unit/parity tests only; no corpus |
| T1 | output-affecting change | 3 heavy meshes (100827, 1038441, metal-nut), `--quality --exclude-nondeterministic --jobs 4` (or `--byte --deterministic`) |
| T1+ | organic/scan-touching change | T1 + 100281, 224108, 46012 |
| T2 | before merging a repair-path PR | all 40 tracked meshes (`git ls-files`), same mode |
| T3 | before a release | T2 + the local hard set and local reference bench (private paths only) |

`--byte` is for refactors (byte-identical baseline vs candidate);
`--quality` is for behaviour changes (no mesh worse on watertight, SI-after,
two-sided Hausdorff, MC-GWN union volume, parts). The baseline half is cached
by input SHA + flags + baseline HEAD, and `--jobs 4` runs meshes in parallel.
Rust-only unwired changes skip the corpus (T0 only). T0 is CI; T1/T2/T3 are
developer/lead gates. Measured on the local M2: T1 138.7 s cold / 73.5 s warm;
T2 338.2 s cold / 169.2 s warm (baseline cache + `--jobs 4`).

## Tests (no framework — plain scripts, need the venvs installed)

- **Repair modes (`repair.MODE_PARAMS`, CLI `--mode`, GUI picker).** Five-step Stage 1 aggressiveness ladder: `low {8,200}`, `medium {8,1000}` (historical default thresholds), `auto` (the default; runs classify_mesh + tuning gate exactly as before — mode-neutral for all existing tests/CI), `aggressive {12,3000}`, `extreme {20,10000}`. Fixed modes (not `auto`) bypass the classifier for parameter selection (it still runs, cheap, so detected_type/confidence stay informative) and set `tuning_applied=False`. The chosen mode lands in the report as `repair_mode` (JSON), a `Mode:` line (`--human`), and per-object for multi-object 3MF. `mincomponentsize` stays >= 8 for every mode (never lower: CI regression risk). Note: `extreme` with mincomponentsize=20 can delete a whole object whose connected part has < 20 faces (e.g. the 13-face broken.stl smoke cube) — that is the value's intended-but-aggressive behaviour. When extreme deletes ALL geometry (zero faces remain), the report carries `category=error` with issue `extreme_removed_object` and the clear message "Extreme mode removed all geometry (small connected component below the size threshold); try a less aggressive mode (e.g. Auto)" — reported distinctly from the generic `malformed`/`all faces are degenerate` error via `repair.ExtremeRemovedAllError` + `classification.classify` (GUI localizes it through the `issue_extreme_removed_object` EN/TR dictionary entry). The GUI exposes the same five modes via its batch-wide Repair Mode button.
- **Extreme extra passes (Stage C).** Only in `extreme` mode, after the main chain (`repair.extreme_extra_passes`), the exact Rust classifier selects self-intersecting faces, the array-only remove-selected-faces + remove-unreferenced-vertices passes delete them, and the main chain runs ONE more time with the same thresholds to catch the newly exposed holes/debris. No self-intersections -> the block is skipped harmlessly. The report carries `extreme_passes_applied` (true/false; also on `--human` as an "Extreme passes" line) plus `self_intersections_found`/`self_intersections_removed` when they ran. `meshing_isotropic_explicit_remeshing` (full remesh) is deliberately OUT OF SCOPE — it can unpredictably change topology; do not add it.
- **Join-closest-components prototype (`repair.join_small_components`, flag `--experimental-join-components`).** FAZ4 prototype, NOT in the default chain: when the flag is set, `stage1_chain`/`delete_fallback_chain` DROP the `meshing_remove_connected_component_by_face_number` step and `repair_mesh_from_arrays` instead moves every connected component below `mincomponentsize` onto the nearest larger component (union-find components; each small component is translated so its closest vertex coincides with the nearest larger-component vertex, then duplicate vertices are merged, non-manifold vertices repaired and holes re-closed). It is a deliberate geometry change (debris is MOVED, not deleted) so it must stay behind the flag; the report carries `experimental_join_components` ({moved, remaining_small}) when it runs. Threaded through `repair_file`/`repair_3mf`/`process_file`; GUI batch-wide checkbox `chk_join_components` (FAZ14, same pattern as `chk_edge_tiebreak`). Regression-tested by `tests/test_join_components.py` (default deletes the small component, flag moves it onto the cube; the GUI checkbox test runs in a subprocess to isolate the Qt main window).
- Smoke: `python3 tests/make_broken_stl.py /tmp/broken.stl && sutura /tmp/broken.stl --human` — generates a cube with missing face, inverted winding, duplicate/degenerate/self-intersecting triangles.
- `~/.local/share/sutura/venv/bin/python tests/torture_tests.py` — manual torture harness (5M-sphere timing, thin wall, multi-part, scan mesh, and a self-intersecting-pair scenario run in `--mode extreme` that must report `extreme_passes_applied=True` and drop self-intersections to 0). Uses `$SUTURA` if set, else the in-repo entry point (this interpreter running `sutura/repair.py`).
- `~/.local/share/sutura/venv/bin/python tests/make_layered_multiobject_3mf.py --check` — layered/folded-vertex 3MF regression. It now generates THREE objects (two layered + one clean closed cube), honors `$SUTURA` (fallback: the in-repo entry point, this interpreter running `sutura/repair.py`), and asserts every object repairs two-manifold with no soup corruption. The layered objects only survive because `stage1_chain`/`delete_fallback_chain` run a SECOND `meshing_remove_duplicate_faces` right after `meshing_remove_duplicate_vertices` (vertex dedup is what *creates* the duplicate faces on a layered mesh); without it, `meshing_repair_non_manifold_edges` sees a per-edge face soup and deletes the mesh (the macOS "all faces are degenerate" failure, documented in `docs/stage2-3mf-per-object.md` Investigation A).
- `~/.local/share/sutura/venv/bin/python tests/test_pinched_vertices.py` — pinched-vertex split on a closed stage-1 result: synthetic bowtie becomes two-manifold (vertex duplicated, faces and holes unchanged), a clean and an open cube are left alone, and thingi10k_145065 repairs two-manifold (category `watertight` when stage 2 is available).
- `~/.local/share/sutura/venv/bin/python tests/test_deep_repair.py` — deep-repair ladder: `full` equals the pre-ladder output (also with a faked fTetWild tier), `off` reports `deep_repair.available` on thingi10k_100827 and nothing on a clean cube, `local` keeps every face outside the deleted region (sphere with a cap removed) and its guard rejects a result that moves them, mode resolution precedence and the CLI flag / `--human` line. No fTetWild needed.
- `~/.local/share/sutura/venv/bin/python tests/test_adversarial.py` — malformed-input rejection; the CLI defaults to the **in-repo** entry point (this interpreter running `sutura/repair.py`, so it never silently uses a stale global install); set `$SUTURA` to run it against an installed CLI instead.
- `python3 tests/test_updater.py` — auto-update license-boundary logic: `crosses_license_boundary()` stops a v0.1.x install from silently jumping to v0.2.0+, allows post-boundary patches, and never fires on malformed input.
- `python3 tests/test_classification.py` — classification stdlib-only rule (importing it must not pull in numpy/pymeshlab) plus the documented category/issue scenarios (watertight, volume warning, stage 2 skipped/error, partial, malformed).
- `python3 tests/test_defects.py` — defects stdlib+numpy-only rule plus hole/non-manifold detection on a clean cube and a cube with a removed face / duplicated face.
- `python3 tests/test_confidence.py` — confidence stdlib-only rule plus high/medium/low score scenarios (watertight, watertight-with-caveats, partial, error) and pre-repair estimates; also checks the tuning gates match `repair.py`.
- `~/.local/share/sutura/venv/bin/python tests/test_mesh_classifier.py` — mesh classifier stdlib+numpy-only rule (subprocess check) plus mechanical (cube), organic (sphere), and unknown-fallback (cylinder) decisions, confidence monotonicity, high-confidence-on-clean-boxes, and non-zero unknown proximity. Needs the venv because it builds test meshes with trimesh.
- `~/.local/share/sutura/venv/bin/python tests/test_mesh_classifier_v2.py` — v2 (experimental, now the DEFAULT) engine invariants: stdlib+numpy-only, `classify_mesh` keeps the classic drop-in shape, head-disabled v2 equals classic, synthetic set stays 100%.
- `~/.local/share/sutura/venv/bin/python tests/test_repair_mode.py` — repair-mode regression: every `--mode` value reports its own `repair_mode`, the default (no flag) is `auto` and is byte-identical to `--mode auto` (same detected_type/confidence/tuning_applied/category), invalid values are rejected, and `--human` shows the `Mode:` line. Uses the repo `repair.py` under the venv, not the installed CLI.
- `~/.local/share/sutura/venv/bin/python tests/test_validate.py` — validate + `--dry-run` regression: `validate` reports the documented JSON fields on clean/broken/multi-object-3MF meshes and NEVER modifies the input; `--dry-run` reports the plan and writes NO file (directory listing unchanged, no `_fixed`); malformed input exits 1. Uses the repo `repair.py` under the venv.
- `~/.local/share/sutura/venv/bin/python tests/test_stage2_3mf.py` — per-object Stage 2 regression for multi-object 3MF: every object gets its own report; a stage-1-closed object gets a per-object `stage2` (ok when the Rust Manifold core is available, honest `Stage 2 skipped` otherwise); the `objects_watertight`/`objects_stage2_ok` aggregates agree; byte-identical objects each get a report (geometry cache); the output round-trips as a valid zip. Uses the repo `repair.py` under the venv.
- `~/.local/share/sutura/venv/bin/python tests/test_obj_repair.py` — OBJ repair regression: a broken OBJ (same defect set as make_broken_stl.py) repairs to a two-manifold `_fixed.obj` with `material_discarded=false`; an OBJ with `mtllib`/`usemtl` references reports `material_discarded=true` (JSON) and a `Material:` line (`--human`) WITHOUT changing the category (cosmetic field, not an issue); lone `mtllib`/`usemtl` lines each trigger the flag. Generates inputs with `tests/make_broken_obj.py` (`--material` variant included). Uses the repo `repair.py` under the venv.
- `QT_QPA_PLATFORM=offscreen ~/.local/share/sutura/venv/bin/python tests/test_heatmap.py` — `focus_frame`/`shared_frame` camera-frame unit tests (centering, zoom magnitude, viewport fit, empty-verts fallback, multi-mesh fit). Needs PySide6 (the venv has it).
- `QT_QPA_PLATFORM=offscreen ~/.local/share/sutura/venv/bin/python tests/test_healed_mask.py` — `healed_face_mask` unit tests (near old defect + no repaired defect = healed; still-broken = not healed; far region = not healed; no old defects = all false; defect cap applied; radius from verts_idx not diameter). Needs PySide6 (before_after_render imports heatmap).
- `QT_QPA_PLATFORM=offscreen ~/.local/share/sutura/venv/bin/python tests/test_before_after_render.py` — before/after render-flow regression: runs `before_after_render.py` as a subprocess on a half-face-defect cube pair and a clean cube pair; asserts all four PNGs are non-empty, main_before + detail_before of the defect pair contain defect-red pixels (> 0), and the clean pair has 0 red everywhere (R=None -> isometric fallback). Needs PySide6 (the venv has it).
- `~/.local/share/sutura/venv/bin/python scripts/verify_before_after_dialog.py` — manual real-display GUI driver: repairs a mesh, opens the before/after dialog and asserts the main + detail images appear and the toggle flips both. Run when the dialog or BeforeAfterWorker changes.
- Classifier calibration harness (NOT a pass/fail test): `~/.local/share/sutura/venv/bin/python scripts/calibrate_classifier.py` runs `classify_mesh` over the labeled synthetic set from `tests/make_classifier_set.py` (boxes/gears/lattices/extrusions vs spheres/torus/capsule/blob, several LODs, damaged variants) and reports per-class precision/recall, unknown rate and confidence separation. Use it to check the effect of any confidence/threshold change; the set is deterministic (seed 42).
- Repair-corpus benchmark (NOT a pass/fail test): `~/.local/share/sutura/venv/bin/python scripts/benchmark_repair_corpus.py <corpus_dir> <out.json>` runs the current pipeline (auto mode) over every STL in a corpus and measures a **strict watertight** verdict with `defects.detect()` on the actual output arrays (`holes == 0 and non_manifold == 0`), recording the pipeline's own category alongside so claim-vs-check discrepancies are visible. Used for the 115-mesh scan corpus (`/tmp/sutura_corpus_100`) re-measurements; the results feed `docs/repair-benchmark-strict-watertight-2026-09.md`.
- Synthetic defect injection (FAZ13): `~/.local/share/sutura/venv/bin/python scripts/defect_injector.py in.stl out.stl --hole --non-manifold --count 5` corrupts a mesh with selectable defect types (`--hole`/`--non-manifold`/`--self-intersect`/`--flipped-normal`/`--degenerate`, any combination; `--count`/`--seed`) and writes a NEW file (input never modified). Validated by `tests/test_defect_injector.py`: hole/non-manifold via `defects.detect()`, flipped/degenerate via `defects.defect_type_colors()` (orange/yellow), self-intersect via the exact Rust classifier. Note: the `defect_type_colors` flipped test taught us that a clean, consistently-wound closed mesh must have ZERO colored faces — an inconsistent-winding cube fixture will false-positive (use the verified `_cube()` in the test, not an arbitrary quad builder).
- `tests/real-world-samples/` (Thingi10K + Artec, original per-model licenses) are genuinely broken and hard-classify models; see its README for expected results and `docs/ATTRIBUTION.md` for the full per-file attribution. The corpus is 40 meshes (Phase 2 grew it from 16 with a deliberately hard curved/free-form mix, CC BY / CC0 only).
