- **fTetWild tier default (after 0.4.1):** `repair.resolve_ftetwild()` maps the CLI to `ftetwild` = `'auto'` (default), `False` (`--no-fallback-ftetwild`) or `True` (`--experimental-fallback-ftetwild`). `'auto'` runs only when `repair.ftetwild_available()` (pytetwild present in the main venv / venv311 fallback site-packages or findable by the current interpreter; no import) and stage 1 still leaves holes or non-manifold edges; `True` keeps the original trigger (also closed-but-SI results) and the explicit skip report. Library functions keep `ftetwild=False` as their default. GUI: `chk_fallback_ftetwild` (checked by default, unchecked -> `--no-fallback-ftetwild`) + `chk_ftetwild_si` (-> `--experimental-fallback-ftetwild`), mapped by `MainWindow._sync_ftetwild`. The tier is installed by default (`install.sh` uses the main venv, `venv311` only as an out-of-range-interpreter fallback; `SUTURA_WITH_FTETWILD=0` opts out). Measured on the 40 real-world samples: strict watertight 31 -> 39, total time 64 s -> 669 s ('auto') vs 2,595 s ('always', which also remeshes 7 closed meshes). fTetWild is non-deterministic (output and time vary between runs, even with num_threads=1). Regression: `tests/test_ftetwild_default.py` (fTetWild-dependent checks skip without the tier).
- `sutura/ftetwild_bridge.py` + `--experimental-fallback-ftetwild` (CLI) / GUI batch-wide checkbox `chk_fallback_ftetwild` is the guaranteed-correct fallback tier (FAZ17) for meshes where stage 1 (autorefine included) STILL leaves self-intersections/holes/non-manifold edges: it tetrahedralizes the ORIGINAL input surface with fTetWild (via the `pytetwild` wrapper, MPL-2.0 — file-level copyleft, compatible with PolyForm-Noncommercial; plain TetWild is GPL and MUST NOT be used) and extracts the boundary triangles (faces incident to exactly one tet) as a watertight, SI-free mesh. `ftetwild_bridge.py` uses a venv311 subprocess on Linux when the main interpreter is out of range (`run_ftetwild`) or an in-process fallback in single-env installs; input via trimesh, output OBJ + JSON report (`input_vertices`/`input_faces`/`output_vertices`/`output_faces`/`time`/`ok`). In `repair_mesh_from_arrays` it runs AFTER the whole stage-1 chain (autorefine + delete-fallback + join-components) and BEFORE the final holes/nm measurement, triggers only when the current result still has SI/holes/nm, and adopts only when `cand_holes <= base_holes and cand_nm <= base_nm` (same guard as autorefine). Report key `experimental_ftetwild` (`ran`/`time`/`output_faces`/`output_holes`/`output_non_manifold`/`adopted`/`error`); `--human` shows a "fTetWild fallback (experiment)" line; GUI repair log shows it too. Measured (auto mode): 100281 3677→0 SI (adopted, ~55s), 100827 11→0 (adopted, ~0.5s); 1038441's raw fTetWild boundary is non-manifold (0 SI, 0 holes but 531 nm edges), which is why the boundary goes through a manifold3d post-process (`repair._ftetwild_manifold_postprocess`, report key `manifold_postprocessed`) before the adopt guard: it rebuilds the boundary via the stage-2 bridge when it has holes or non-manifold edges OR is closed but not two-manifold (pinched "bowtie" vertex where two tets meet in one vertex — without this stage 2 never ran and a strictly watertight result ended as `warning`, e.g. thingi10k_248395), and keeps the rebuild only when it is no worse on holes and nm edges. Regression: the synthetic bowtie tests in `tests/test_ftetwild_default.py`. If a case turns up where the rebuild does not make the boundary two-manifold, the planned fallback is `meshing_repair_non_manifold_vertices` on the fTetWild boundary (not implemented). Measured on the 40 real-world samples on macOS (auto, 2026-09-25): strict watertight 39/40, category watertight 38/40, ~354 s total; 1038441 is adopted (`manifold_postprocessed=True`, 25.8 s, watertight), so the old "1038441 declined" note no longer holds; the only strict failure is artec_metal-nut (fTetWild timeout at the 180 s budget, 2 holes left, `warning`). `requirements-ftetwild.txt` pins `pytetwild==0.4.2` only (PyVista/VTK were dropped; `ftetwild_bridge._import_pytetwild` stubs the optional PyVista accessor); on Linux the tier installs into the main venv, with the venv311 subprocess path as the out-of-range-interpreter fallback; `venv311` is created only when needed. history.py records `ftetwild_applied`. **Shape flag (2026-09-26):** after the holes/nm guard, `_ftetwild_tier` computes `repair._hausdorff_rel(input, candidate)`; above `FTETWILD_MAX_HAUSDORFF_REL=0.01` the result is STILL adopted but flagged (`experimental_ftetwild.shape_changed`, top-level `shape_changed`, issue code `shape_changed` in `classification.py`, category unchanged; GUI labels `issue_shape_changed` EN/TR). A holes/nm rejection reports `reject_reason='holes_nm'`. **Size limit:** inputs with more than `FTETWILD_MAX_FACES=300000` faces skip the tier (`ran=False`, `reject_reason='too_large'`, not in `tiers_run`, not offered in `deep_repair.available`). The corpus face counts are not in the repo: verify with the benchmark's `input_faces` column. **Retry (deterministic, v0.9.1):** `_ftetwild_tier` runs `_ftetwild_attempt` (fTetWild + manifold3d post-process) with the bridge defaults first; if that boundary fails the holes/nm guard it retries once with `FTETWILD_RETRY_PARAMS={'optimize': True}` — a pure function of the guard verdict, NOT of the elapsed wall clock (the old `FTETWILD_RETRY_MIN_SECONDS=10` gate and `retry_skipped='budget'` were removed). `FTETWILD_TIMEOUT` is only an outer all-or-nothing abort checked between attempts: when it trips (or an attempt returns `error='timeout'`) the tier is abandoned and the previous stage result is kept (`report['experimental_ftetwild']['aborted']=True`, `reject_reason='aborted_time'`, message `FTETWILD_ABORT_MESSAGE`), never a partial attempt; `--human` prints it and the GUI shows `repair_log_ftetwild_aborted` (EN/TR). - **Mirror completion (`sutura_engine/mirror.py`, #14) and thin-wall analysis /
  thicken (`sutura_engine/wall.py`, #15, v0.6.1).** The legacy top-level paths
  `sutura/mirror_repair.py` and `sutura/wall_thickness.py` are thin
  `sutura_engine.mirror` / `sutura_engine.wall` re-export shims. #14 detects the dominant
  boundary loop's symmetry plane (`detect_mirror_plane`: planarity x dominance
  score) and `mirror_close` reflects the visible surface across it (winding
  flipped so the shared boundary edges cancel), welds the seam, and fuses
  overlapping halves with `hull.extract_outer_shell`; low confidence or an
  invalid stitch falls back to the native implicit closer (`closing.poisson_close`,
  kept as the legacy function name). It is wired into
  `repair.closing_ladder` as `closing='mirror'` and guarded input→output.
  `wall_thickness` builds a signed-distance grid (area-weighted surface samples
  + nearest-normal sign), estimates per-vertex thickness by an inward ray march
  to the first crossing (opposite-normal fallback) and `thicken_to_min` offsets
  thin walls by a morphological dilation (`delta=(target-min)/2`, capped at 25 %
  of the bbox diagonal) re-extracted with a dependency-free marching-tetrahedra
  pass; `repair.wall_thicken_tier` runs it on the original input, cleans with
  the native passes and adopts only a strict-watertight, no-worse candidate. CLI
  `--wall-min-thickness T` (default 1 % of the bbox diagonal). The engine
  modules ship inside the copied `sutura_engine` package; the top-level shims
  `mirror_repair.py` / `wall_thickness.py` must stay in the module lists of
  `install.sh`, `install-macos.sh`, `scripts/build_appimage.sh`,
  `updater.APP_MODULES` and `build-macos.yml`.
