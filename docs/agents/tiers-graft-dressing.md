- **Graft (#13, shell wrap) — `sutura_engine/graft.py` (real) + `sutura/shell_wrap.py` legacy shim:** a pure API `shell_wrap(verts, tris, *, r=None, voxel=None, box=None, local=None, remesh=True, fill_cavities=False, max_tries=3, target_edge=None, si_check=True, guard=True, grid_budget=None, detail_tol=None, intensity=None, sign_field=None) -> (v, t, report)` with NO dependency on `methods.py`/the registry (imports numpy/trimesh/`sutura_geom` + pure helpers from `repair.py`/`defects.py`). Display name **Graft** (`report['display_name']`), `invents_geometry=True`. **Grid budget (2026-10, deterministic):** `resolve_grid_budget(intensity)` is a PURE function of the explicit Triage intensity preset (`quick`/`balanced` 1.5M, `thorough` 10M, `extreme` 25M; Balanced keeps the historical 1.5M after the corpus regression check showed the 5M target doubled Graft time for no watertight gain), clamped to `[GRID_BUDGET=1_500_000, GRID_BUDGET_HARD_MAX=25_000_000]`. It never reads free RAM, so the same input plus the same options yield the same grid on every run and machine (the 0.9.0 RAM-clamp that could go below the floor was removed as a determinism bug). Free RAM is a DISCRETE FALLBACK guard (`_grid_budget_fits_ram`): when the auto budget would not fit (`grid_budget * GRID_BUDGET_BYTES_PER_CELL=56 > available * GRID_BUDGET_RAM_RESERVE=0.35`), `shell_wrap` falls back once to the Balanced budget (`resolve_grid_budget('balanced')`, 1.5M), reporting `report['grid_fallback']={from,to,intensity}` and a `grid_fallback` warning and continuing; only when even Balanced does not fit does it return the input unchanged with `report['low_memory']=True`, `reject_reason='low_memory'` and a clear message, and `graft_tier` keeps the stage-1 result (`rec['low_memory']=True`). The resolution is never silently coarsened (`graft_tier` surfaces `rec['grid_fallback']` and `--human` prints a "Graft grid" line for the fallback/refusal). Explicit `grid_budget=` values (e.g. test budgets) are honoured verbatim and not guarded. **Closing ladder (2026-10, deterministic):** the r-ladder stops on a deterministic WORK budget (`GRAFT_WORK_BUDGET_BY_INTENSITY` = `(MAX_TRIES+1) *` the preset grid budget, units = the sum of grid cells `_grid_cell_count` over attempts, a pure function of the input grid + preset), so the produced mesh never depends on CPU speed or load; `report['budget_limited_by']='work'` on that stop (current presets do not reach it, so outputs are unchanged). The wall clock survives ONLY as an outer all-or-nothing abort (`time_budget`, checked between attempts): when it trips, `shell_wrap` discards the partial ladder and returns the input unchanged with `report['aborted']=True`, `reject_reason='aborted_time'` and the plain message `GRAFT_ABORT_MESSAGE` ("Graft was stopped for time (...); the stage-1 result was kept"), and `graft_tier` sets `rec['aborted']=True` / `rec['timed_out']=True` and keeps the stage-1 result; `--human` prints it and the GUI shows `repair_log_graft_aborted` (EN/TR). A deterministic work-budget stop is `rec['budget_limited_by']='work'` / `reject_reason='budget'` (GUI `repair_log_graft_budget`). `graft_tier`/`deep_repair_ladder` pass the preset's `base`/`name`, so CLI and GUI parity is automatic (both already send `--intensity`). The `shell_wrap` report carries the effective `grid_budget`, `intensity` and the chosen `voxel`; the top-level `report['graft']` surfaces the guard outcomes (`grid_fallback` / `low_memory`) but not `grid_budget` itself. **Sign-field Pass 0 (default OFF, opt-in):** when enabled, Graft runs `morph_close(..., r=0)` — the raw GWN sign field (with the ray-stab vote when `raystab` is on), no dilation/EDT — before the closing ladder, so genuine gaps stay open; it is adopted only when the strict X-Ray reload verdict is watertight AND the existing healthy-detail gate passes, otherwise the closing ladder runs unchanged. Pass 0 forces whole mode (a local window is meaningless at r=0), uses `r_eff=voxel` for the projection/behind-on-healthy thresholds (`r_used` is reported as 0, mode `sign_field`), and is prefixed to `r_ladder`; enable with `sign_field=True` / `SUTURA_GRAFT_SIGN_FIELD=1` (`SIGN_FIELD_SUPPORTED` on the extension gates it, falling back when absent). It is OFF by default because on ornate-frame (396 k faces) it fails both gates at once — 2 holes / 105 non-manifold edges and 1.29 % detail loss vs the 0.25 % gate — and wastes ~326 s for a result the verbatim hybrid reproduces. A sign-field candidate that is watertight but fails fidelity is never recorded as `best` (it could otherwise block every closing-ladder attempt, both having 0 holes+nm, and be adopted with a changed shape). Pipeline: **auto voxel = the input's median edge** (coarsened only to fit the `grid_budget`; keeps the output face count in the input's order — an earlier "finest budget allows" rule over-refined and exploded the face count) → **r-ladder** starts at `0.0` (Pass 0, when enabled) then `1.5*voxel`, growing ×1.6 (`R_STEP`) only while the result is not reload-watertight, capped by `min(2 % diag, 0.5*hole estimate)` (the hole estimate sets only the top) → `sutura_geom.morph_close` → **refine (split) the envelope to the median healthy edge BEFORE projecting** (capped at `min(REFINE_MAX_FACES=300k, 4×input faces)`; a finer envelope is left alone, never collapsed) → **projection** onto the original where `dist < 1.5 r` AND `dot(env_normal, orig_normal) > 0.5` → **SI rollback** (proper crossings only, adjacent faces ignored; skipped above `SHELL_WRAP_SI_MAX_FACES=20000` for speed) → **Stitch (P-WELD)** (`_separate_weld_collisions` + `repair.p_weld_final`, both array-native) → **X-Ray honest verdict**. **Verbatim hybrid fallback** (when the envelope is not reload-watertight or fails fidelity): keep the original healthy triangles byte-identical, drop only the damaged-region faces, close with the native repair path (`_hybrid_close`: non-manifold repair, duplicate-face and unreferenced-vertex removal, `close_holes`) plus a numpy centroid-fan boundary cap (`_cap_boundary_loops`), then Stitch; adopted only when reload-watertight. **Fidelity gate = the exact healthy original→result deviation** (`_detail_loss` max / bbox diagonal) against `HEALTHY_HAUSDORFF_MAX=0.0025` (0.25 %); the result→original direction counts the repair caps and is reported as `hausdorff_healthy_behind` (informational), as is the all-input `hausdorff_one_sided`. `report['fidelity_ok']` is the key the auto policy must check before preferring Graft over fTetWild (if False, try both and keep the lower-deviation watertight result). **Detail loss:** `report['detail_max_mm'/'detail_mean_mm'/'detail_tolerance_mm'/'detail_area_moved']`, `report['warnings']` (EN/TR `detail_loss` + `fidelity`) and `report['per_vertex_deviation']` (per result vertex, for the heatmap). **Local mode** (damaged bbox <30 % of the model bbox) runs `morph_close` with `box=` and stitches by boolean union (`_stitch_local`, manifold3d); a non-watertight original makes the boolean fail and the tier falls back to whole mode. New `sutura_geom` API: `closest_points(verts, tris, points) -> (xyz, dist, face_idx)` (parallel BVH closest-point), `self_intersecting_faces(verts, tris) -> (mask, count)` (proper crossings only, adjacent faces ignored, `SI_MAX_FACES=150000`, `-1` when skipped), and `morph_close(..., surface="dual"|"tets")`. Regression `tests/test_shell_wrap.py` (9 passed). **Known limitation:** dual contouring can leave geometry-level self-intersections on curved fields (topologically manifold but ~2 % of faces cross), which is why the robust path is the verbatim hybrid. `tests/bench_shell_wrap.py` is the F4 harness: only meshes whose default repair is NOT already reload-watertight, Graft vs the real `repair.py --methods 7`, one mesh at a time, 600 s cap; on the 13 damaged real-world samples Graft is 13/13 reload-watertight (fTetWild 12/13), total 326 s vs 869 s, with healthy deviation ~0 (fTetWild up to 4.7 %). **Registry/tier integration (F3 items 2/3/4, `feat/engine`):** the engine module is registered as method **#13**, slug `graft`, display name **"Graft"** (`sutura_engine/methods/builtin/graft.py`, `graft_available()` = Rust `sutura_geom.morph_close` + numpy/trimesh; `self_guarded=True` so the generic input→output guard is skipped). Registry aliases `13`/`m13`/`graft`/`shell_wrap`/`wrap` → 13; method 12 `transplant_plus` no longer owns `13`/`graft` (BREAKING vs 0.6.0, noted in CHANGELOG `[0.7.0]` and `--methods --help`). Templates `organic`, `single_side_scan`, `dense_scan_heavy_si` prefer #13 before #7. **Auto policy:** the CLI resolves `graft` via `resolve_graft` (default `'auto'`, `--no-graft` / `--experimental-graft`, env `SUTURA_GRAFT`); `deep_repair_ladder` tries Graft on the original BEFORE the fTetWild tier — if Graft is reload-watertight and `fidelity_ok` it is adopted and fTetWild is skipped; if it closes but `fidelity_ok` is False, fTetWild is also tried and the watertight result with the lower healthy deviation wins (`report['graft']['reason']` records the supersession). The library default `graft=False` keeps direct `repair_mesh_from_arrays(deep_repair='full')` byte-identical. `classification.classify` adds the `graft_detail_loss` issue only for an *adopted* Graft with warnings (never changes the category); the GUI localizes it and the repair-log line EN/TR (it reads the method's own EN/TR message). `report['graft']` carries fidelity/detail stats and warnings; `--human` prints a `Graft (shell wrap)` line. Packaging: `shell_wrap.py` is in the top-level module lists and `sutura_engine/graft.py` ships in the copied engine package; CI runs `tests/test_shell_wrap.py` in the rust-geom job. Both the pre-existing stale `tests/test_ftetwild_default.py::test_auto_leaves_closed_si_result_alone` (stage 1 no longer leaves SI on thingi10k_100045) and the GUI method-tag persistence question were checked: GUI method tags live only in `MainWindow._method_tags_by_path` (in-memory, never serialized), so no migration is needed. The full real-world corpus expected results are NOT re-baselined in this batch (auto now prefers Graft) — a follow-up corpus re-measurement is required before a release.

- **Dressing (#16, variable-viscosity volumetric skinning) — `sutura_engine/dressing.py`, opt-in.** The surgical sibling of Graft: the input is dipped in a spatially varying "liquid" and the `F(x) = s(x) - r(x)` level set is extracted, where `s` is the generalized-winding signed distance (`sutura_geom.sdf_grid`) and `r(x) = r_base + (r_max - r_base) * exp(-d_defect^2 / 2 sigma^2)` a viscosity radius that is thin over detailed healthy surface and thicker over damage (`d_defect` = the Rust `sutura_geom.edt_grid` of the hole / non-manifold / self-intersecting vertex mask). The isosurface of a scalar field is 2-manifold and self-intersection-free by construction; because projecting the coat back onto the input surface re-introduced 7,850 SI faces (measured on ornate-frame and permanently rejected), fidelity comes from a thin `r_base` instead. Pure API `dressing_coat(verts, tris, *, voxel=None, intensity=None, grid_budget=None, r_base=None, r_max=None, sigma=None, guard=True, time_budget=None, drain=None, defects=None, r_max_scale=None, sigma_scale=None) -> (v, t, report)` (`report['display_name']='Dressing'`, `invents_geometry=True`). `defects` selects the input defect set driving the viscosity mask (`DRESSING_DEFECT_SETS = ('all', 'holes_nm')`; `all` = holes + non-manifold + self-intersections, `holes_nm` = holes + non-manifold only), and `r_max_scale` / `sigma_scale` multiply the resolved `r_max` / `sigma` (None = 1.0; non-positive / unparseable values are ignored by `resolve_dressing_rmax_scale` / `resolve_dressing_sigma_scale`). All three land in `report['defects']` / `report['r_max_scale']` / `report['sigma_scale']` and are threaded through `repair.dressing_tier` / `repair.deep_repair_ladder` / `repair_mesh_from_arrays` / `repair_file` / `repair_3mf` / `process_file`; the CLI flags are `--dressing-defects {all,holes_nm}` / `--dressing-rmax-scale F` / `--dressing-sigma-scale F` (`SUTURA_DRESSING_DEFECTS` / `SUTURA_DRESSING_RMAX_SCALE` / `SUTURA_DRESSING_SIGMA_SCALE`). **Voxel = the feature anchor** (`_median_edge_length / 1.5`), clipped to the intensity preset's diagonal band (`DRESSING_BY_INTENSITY`: quick 120-200, balanced 200-350, thorough 300-500, extreme 450-800) with a small-model brake (`< 500` faces skips the fine end) and grid-budget coarsening; this fixes the thingi10k_100827 7.3 % oversampling (it was evaluated at `diag/200`). Viscosity defaults `r_base = clip(0.3*ell, 0.25*voxel, 0.8*voxel)`, `r_max = min(r_preset, 3.5*ell, 0.45*gap)`, `sigma = max(2*ell, 2*voxel)`. **Extraction** is a numpy marching-tetrahedra port of the prototype (`mt.py`, per-triangle edge grouping + positional weld) with a BFS face re-orientation + positive-volume flip; the Rust `sutura_geom.dressing_coat` (narrow-band field + coat extractor, `feat/dressing` c2f2116) is feature-detected via `_rust_dressing_coat` and used when present (`report['engine']='rust'/'numpy'`, `info` carries `band`/`band_cells`/`field_seconds`/`manifold`), falling back to numpy on any error. The Rust binding is `dressing_coat(verts, tris, defect_pts=None, voxel=None, r_base=None, r_max=None, sigma=None, band_voxels=2.0, margin_voxels=3.0, drain=0.0)` — `defect_pts` is an **Nx3 point array** (the Python layer converts its defect vertex indices) and `drain` carries the healthy-region erode-back `delta_r`; the Python layer feature-detects the parameter via `_rust_signature_has_drain` (introspection + a keyword probe) and falls back to the numpy path for a positive drain when the installed extension predates it. The reported `defects` / `r_max_scale` / `sigma_scale` are resolved in the Python layer before dispatch, so they apply to both engines. **Decimation** (`_decimate_coat`, target `max(min(F_in, 500k), 50k)`) uses the native `sutura_geom.decimate_qem` (meshopt; 0 SI, sub-micron fidelity, ~20 s per the decimation benchmark; the report recommends `min(N_input, 400k)`, and a 2-step schedule runs when the target <= half the raw coat) and rolls back atomically to the un-decimated coat on any holes / non-manifold / exact-SI violation. **Component cleanup (`_clean_coat_components`, before decimation):** the extracted triangle soup is split into vertex-connected components (stdlib/numpy `topology.connected_components`) and the extraction debris — a component below `CLEANUP_MIN_FACES=64` OR `CLEANUP_ABS_VOXELS=32 * voxel^3` OR `CLEANUP_REL_VOLUME=1e-3 * largest|vol|` (thresholds measured on the 145065/63785/1038439 coats: debris <= 932 faces / ~0.6 voxel^3, smallest genuine shell 10 176 faces / ~5 000 voxel^3) — is dropped; a surviving inverted component is kept only when it is nested (bbox) inside a kept positive component AND the input's generalized winding number (`PyMeshBvh.winding_points`, built over `v0`/`t0`) at its centre is `< 0.5`, i.e. the input is genuinely empty there (a true cavity, e.g. a hollow-shell input). Positive components must also overlap the input bbox. It never raises (`ran=False` on any failure), is a byte-identical no-op for a single-component coat, and falls back to the untouched coat if it would remove all geometry; `report['cleanup']` (surfaced by `repair.dressing_tier` as `report['dressing']['cleanup']`) carries `components_before/after`, `kept_positive/kept_cavities`, `removed_debris/negative/other`, `removed_faces/volume` and the thresholds. Measured on the 13-mesh `dressing_tuned` set (2026-10): 145065 669 -> 1, 63785 25 -> 1 (both OrcaSlicer `number_of_parts` 1 after), ornate-frame 8 -> 1; 1038439 keeps its 3 genuine material lumps (its input Orca `number_of_parts = 6`, so the remaining `number_of_parts = 3` is an input property, not a Dressing failure). **SI cap caveat:** the exact classifier only verifies at <= `SI_MAX_FACES` (150k today), so `si_after=None` above that reads as "unknown" and adoption accepts it; once the Rust cap is raised the same `_exact_si` call verifies the coat with no code change. **Drain ("erode-back", `dressing_coat(drain=...)`, `_resolve_drain`):** the coat sits ~`r_base` OUTSIDE the original (dimension growth); the drain is applied **in the level set** (`F = s - r + delta_r`, `_numpy_coat`/`_rust_dressing_coat`), NEVER by vertex projection (which re-introduced 7,850 SI and is permanently rejected). `drain=None` uses the preset's `drain_factor` (`DRESSING_BY_INTENSITY`: quick 0.0 off, balanced/thorough 1.0 full, extreme 1.25 deep per the offset report), and the argument also accepts a mode name (`none`/`half`/`full`/`deep` in `DRAIN_MODES`) or an explicit `delta_r` in mm. Full drain reduces healthy growth ~40 % (median +0.33 -> +0.20 mm raw) with a ~4 um median inward dip and keeps defects covered; `report['drain']={'mode','factor','delta_r','amount','drained'}`. Resolution: `repair.resolve_dressing_drain` (`--dressing-drain MODE|mm` > `SUTURA_DRESSING_DRAIN` > None). **Known residual:** a ~0.2 mm (~0.4 voxel at 0.5 mm) outward bias remains even at full drain — the extractor's discretization, to be addressed in the Rust core, NOT hidden with vertex projection. **Adoption** (`repair.dressing_tier`): strict reload-watertight AND `si_after in (0, None)` AND `report['fidelity_ok']` (coat->input max deviation below the preset gate: 1.5/0.8/0.4/0.25 % of the diagonal) AND three shape-preservation gates against the result the ladder held before Dressing — signed-volume delta `<= repair.DRESSING_MAX_VOLUME_DELTA` (0.10), component-count growth `<= repair.DRESSING_MAX_PARTS_SLACK` (1) and healthy-surface P95 coat-vs-input **vertex-normal** angle `< repair.DRESSING_MAX_NORMAL_ANGLE_P95` (30 deg, PLACEHOLDER; measured Dressing p95 is 12-36 deg on the accepted 13-mesh coats and 82-88 deg on ornate-frame / 100281 / 1038439 / 1038441 / 145065). The normal metric is `dressing.normal_angle_deviation(wv, wt, v0, t0, defect_idx)` (nearest input vertex via `sutura_geom.nearest_points`, healthy = nearest input vertex not in `defect_idx`, returns p50/p95/p99/max/n; `None` without the nearest-neighbour backend) with `_vertex_normals`; the helpers `dressing.si_face_count` / `signed_volume` / `count_components` sit beside it, and `dressing_coat` reports `normal_angle_p*` / `components_after` / `volume_after`. `repair.cad_likeness(verts, tris)` returns `{'score','planar_fraction','sharp_fraction','cad_like'}` (flat edge < 1 deg, sharp > 30 deg, score = max; cube 0.667 cad_like=True, sphere 0.0 False) and is recorded in `report['deep_repair']['cad_likeness']` on every Auto run — the CAD guard hook (the ladder runs Graft first for ALL inputs, so a CAD-like part already gets the verbatim Graft hybrid before Dressing); the calibrated detector will drive the ordering. The candidate is then confirmed by stage 2 at the top level. `classification.classify` adds the `dressing_detail_loss` issue only for an *adopted* Dressing with warnings (never changes the category). `report['dressing']` carries the parameters, deviations, exact-SI verdict, EN/TR warnings and time budget; `--human` prints a `Dressing (viscosity)` line. **Auto-ladder fallback behind a single default switch, shipped OFF.** The lib default `repair_mesh_from_arrays(dressing=False)` is unchanged; `repair.resolve_dressing(no_dressing, force, environ, default_enabled)` returns `False` / `True` (forced) / `'auto'` (fallback). Precedence `--no-dressing` > `--experimental-dressing` > `SUTURA_DRESSING` (`0/1`) > the switch `repair.DRESSING_DEFAULT_ENABLED` / `SUTURA_DRESSING_DEFAULT` (`_dressing_default_enabled`); the switch is OFF until the ornate-frame voxel-staircase detail loss is fixed. Under the switch: the `full` ladder runs Dressing after Graft and before fTetWild only when the result it now holds still has holes/NM/positive-exact-SI (`_dressing_wanted` + `_dressing_damage`, an SI-only residual counts as damage; `stats['deep_repair']['dressing_damage']` records the counts), and an explicit force runs it regardless (even under `--deep-repair off`, cf. method #16's `kwargs`); the default library path adds no report key and stays byte-identical. Method #16 is registered (`sutura_engine/methods/builtin/dressing.py`, `dressing_available()` = the module + `sutura_geom.sdf_grid` or `dressing_coat` + numpy/sutura_geom; aliases `16`/`m16`/`dressing`/`coat`/`dipcoat`; `self_guarded=True`, `needs_user_input=True` so it is excluded from the auto ranking) and also selectable via `--methods 16` / the GUI *Use method* menu. GUI parity: the batch-wide `chk_dressing` checkbox (Options → Experimental) adds `--experimental-dressing`; the `cmb_dressing_drain` combo next to it adds `--dressing-drain <mode>` (Preset default / Off / Half / Full / Deep); `cmb_dressing_defects` adds `--dressing-defects <all|holes_nm>` (Preset default / all / holes_nm); and `cmb_dressing_rmax_scale` / `cmb_dressing_sigma_scale` add `--dressing-rmax-scale` / `--dressing-sigma-scale` (Preset default = 1.0, then x0.25 / x0.5 / x0.75 / x1 / x1.5 / x2). Regression `tests/test_dressing.py` (25 passed) plus `tests/test_methods.py`/`tests/test_methods_gui.py`/`tests/test_engine_no_pymeshlab.py` numbering updates.

- **Dressing opt-in UX (`report['suggestions']`, `--dressing-force-adopt`, GUI "Try Dressing").** `repair.process_file` post-processes every result with `_dressing_suggestions(result)` (helper in `repair.py` beside `_dressing_suggestion_text`) and, only when non-empty, sets `result['suggestions'] = [{'method':'dressing','flag','force','reason','warning', ...}]`. HARD RULE: suggestions stay SEPARATE from `result['issues']` — they are a next action, not a defect of this result — so `classification.classify`/`ISSUE_LABELS`/the batch `issue_counts` are NOT touched and the category never changes (do NOT move them into `classification.py`). Cases: not-watertight and Dressing never ran -> `flag=DRESSING_SUGGEST_FLAG` (`--experimental-dressing`), `force=False`; Dressing ran but the shape gates rejected it -> `flag=DRESSING_FORCE_ADOPT_FLAG` (`--dressing-force-adopt`), `force=True`, the gate numbers (`volume_delta_rel`/`normal_angle_p95`/`fidelity_ok`) and the non-adopt reason in `reason`; watertight / error / budget-declined / adopted / multi-mesh 3MF aggregate -> no suggestion. `_dressing_suggestion_text(sug)` renders the `--human` `⚠` hint. `--dressing-force-adopt` (implies `--experimental-dressing`, no env var) threads `dressing_force_adopt` through `repair_file`/`repair_3mf`/`repair_mesh_from_arrays`/`deep_repair_ladder` into `dressing_tier(..., force_adopt=...)`: it bypasses the volume / component-slack / normal-p95 / fidelity shape gates but STILL requires `cand_holes==0 and cand_nm==0 and si_ok`; `rec['forced']=bool(force_adopt and not shape_ok)` and the adopt reason gains `, shape gates forced`. GUI parity: batch-wide `chk_dressing_force_adopt` (Options → Experimental, in `_options_defaults`; `RepairWorker` adds `--experimental-dressing` when `_dressing or _dressing_force_adopt`, plus `--dressing-force-adopt`) and the post-batch non-blocking `btn_try_dressing` (`_refresh_dressing_suggestion` after `_on_all_done`, `_on_try_dressing` sets the checkbox, clears `_suggestion_by_path`, sets `_rerun`, re-runs only the suggested files with `force=True`); EN/TR strings `dressing_force_adopt_label`/`_tip`, `try_dressing_btn`/`_bn`/`_tip`. Regression `tests/test_dressing.py::test_dressing_force_adopt_bypasses_shape_gates` / `::test_dressing_suggestions_payload` and `tests/test_methods_gui.py` (worker both-flags, checkbox/defaults, button re-run).
