- **Rust foundation crate — `rust/sutura-geom` (Phase A of the indirect-predicates roadmap):** a Cargo crate (`cdylib` + `rlib`) exposing a thin PyO3 wrapper `sutura_geom` for the explicit-point robust predicates `orient3d`/`insphere` from the `robust` crate (Shewchuk adaptive-precision arithmetic), pinned to `robust =1.2.0`, `pyo3 =0.29.2` (abi3-py311), `numpy =0.29.0`. It is built with **maturin** (`==1.15.0`, build tool only, NOT a Cargo dep) via `maturin develop --interpreter <venv>/bin/python`; the extension installs into the target venv. Every dependency is license-checked permissive (MIT/Apache-2.0/BSD-2); any GPL/LGPL/AGPL resolution is rejected — the `Indirect_Predicates` (LGPL-2.1) and `OpenMeshCraft` (GPL-3.0) reference implementations MUST NOT be used as code bases, only as algorithmic references. Indirect/implicit predicates, expansion arithmetic, 2D CDT, triangle-triangle intersection and repair-pipeline integration (autorefine.py etc) are deliberately OUT OF SCOPE for this crate — it is foundation-only. Regression-tested by Rust unit tests in `rust/sutura-geom/src/lib.rs` plus `tests/test_sutura_geom.py` (smoke, pytest-compatible; needs the maturin-built extension). Planning docs: `docs/alpha-wrap-feasibility-2026-09.md` and `/tmp/rust-core-research-plan.md`.
- **Splint core — `rust/sutura-geom/src/splint/` (opt-in tier #18).** `sutura_geom.splint_cut(verts, tris, res, adaptive=None|'hardened'|'retry') -> (verts, tris, report)` ports steps 1–8 of the Splint spike: normalized UDF grid → eps-offset dual-contour proxy → sequential Geogram Delaunay PSM → per-tet signed UDF/GWN labels (the ONLY rayon-parallel stage) → min s-t cut → fix-A signed-field island cleanup (fix B off) → inside/outside boundary. `None` is the original path and stays byte-identical; `'hardened'` adds the measured thin-wall adaptive proxy sampling (fixed constants: `THIN_MULT=2`, dot `-0.7`, cos30, 1.5× cap); `'retry'` runs hardened, counts **`cut_shells`** — raw-cut faces joined only across edges used by exactly 2 faces (the `split_components` rule Manifold Stage 2 sees) — and reruns with broad sampling when `cut_shells > 4`. It is method **#18** as an opt-in deep-repair tier (`--experimental-splint`, default OFF; GUI checkbox) and was evaluated on the 40-mesh corpus, adopted on none of them; step 9 (`thin_mesh` dual contouring) remains out, so the raw cut itself is generally not manifold. The Geogram standalone Delaunay PSM is vendored under `rust/sutura-geom/third_party/geogram_delaunay_psm/` (BSD-3-Clause, Inria) and is **mandatory** for `sutura_geom` (prebuilt wheels include it; source builds need C++20); it is compiled with `cc` + C++20 via `build.rs`; `THIRD_PARTY.md` and the Geogram `LICENSE` are included in the wheel (CI checks them with `unzip -l`). Source builds need a C++20 compiler; the prebuilt wheel does not. Determinism contract: serial vs parallel and `RAYON_NUM_THREADS` 1/2/8 are byte-identical for `None`, `hardened` and `retry` (only the diagnostic component-volume float sums use a 1e-12 tolerance); the five reference meshes match the spike fix-A raw cuts byte-for-byte for `None`, the fix-A hardened reference for `hardened`, and the fix-A broad retry reference on the two retry meshes. The retry decision on the five hardened meshes is cut_shells 695/1276/2/1/1, matching the spike (100827 and 1038441 retry, the others do not). The 5-mesh equivalence harness is local (spike outputs in `/tmp`), not CI; `tests/test_splint.py` is the CI-safe cube/five-cube determinism test.

- **Rust morphology core — `rust/sutura-geom` (F2):** new modules independent of the exact-arrangement path. `src/winding.rs` builds a triangle BVH and evaluates the generalized winding number (Barill et al. 2018: exact triangle solid angle for near nodes, dipole far-field for nodes subtending less than `WINDING_FAR_TOL=1e-2` sr) plus branch-and-bound closest-point unsigned distance; signed distance is `sign(w-0.5)*unsigned`; grid queries are rayon-parallel (`rayon = "1.12"`, pure Rust, ~1.1 MB source, MIT/Apache-2.0 — the only new dependency). `src/morph.rs` implements the Felzenszwalb–Huttenlocher exact separable EDT and closing as dilate (`sdf-r`) → true EDT re-distance of the dilated occupancy (so erosion does not cancel the dilation) → erode (`+r`), plus a boundary flood-fill `fill_cavities`. `src/dual_contour.rs` is manifold dual contouring: one Hermite QEF vertex per cell surface component (Tikhonov-regularised symmetric 3x3 eigen-solve, clamped to the cell), quads over sign-change grid edges, and a marching-tetrahedra fallback if the manifold check fails. The Python API is `sutura_geom.sdf_grid(verts, tris, voxel=None, box=None)` and `sutura_geom.morph_close(verts, tris, r, voxel=None, box=None, fill_cavities=False)`; grids cap at `MAX_VOXELS=512^3` with automatic coarsening and accept a sub-`box` window. `r == 0` is accepted as the **sign-field path**: `close_sdf` (and the dilation padding) is skipped and the raw signed field feeds dual contouring directly, so gaps stay open; `info['sign_field']` records the mode and the module exports `SIGN_FIELD_SUPPORTED` so callers can feature-detect it. The Python grid arrays are converted with `Array3::from_shape_vec(...f())` (i-fastest/Fortran order `[i + nx*(j + ny*k)]`); the earlier C-order conversion transposed X/Z and scrambled strides on asymmetric (`nx != nz`) grids — fixed and regression-tested with an asymmetric box in `tests/test_raystab.py`. Regression: `tests/test_morph_geom.py` (hole closes, overlapping cubes fuse, inverted nested shell = retained cavity vs same-orientation shell = absorbed, torus genus preserved, sub-box, cap) and the timing run `tests/morph_timing_1038441.py`. NOTE the EDT re-distance introduces an inherent ~half-voxel surface offset (the occupancy boundary is quantized to voxel centers), so volume checks are tolerant. `cargo build --release -j 4` under `PYO3_PYTHON=<venv>/bin/python`; run `cargo test` binaries with `DYLD_LIBRARY_PATH=<venv>/lib` on macOS; maturin 1.15.0's `develop` in this environment rejects `--interpreter` and takes the env from `CONDA_PREFIX`/`VIRTUAL_ENV` instead (do not set both).
- **Rust ray-stabbing inside/outside vote — `rust/sutura-geom` (`src/raycast.rs`, experimental):** a Nooruddin & Turk (2003) "spray" vote used to disambiguate the generalized-winding sign in the ambiguous band `0.3 < w < 0.7`, where the field alone cannot decide (overlapping unioned shells, inconsistently oriented soups). `winding.rs` gained exact ray casting (`MeshBvh::intersect_ray` -> `RayQuery {net, crossings, nearest_t, suspect}`; `ray_node` traversal ignores the dipole far-field shortcut; `ray_tri_hit` is f64 Möller–Trumbore with sign `sign(dot(dir, n))`, grazing hits flagged, shared-edge hits deduplicated within `1e-6*diag`). The vote is the **oriented net crossing sum** `Σ sign(dot(dir, n_face))` (`> 0` inside; correct union/cavity semantics and reduces to parity for a single consistent shell), with each ray falling back to crossing parity when `net < 0` or `(net == 0 and odd)`; `parity=True` forces parity for all rays. An escaping ray (zero hits) is an outside vote weighted `escape_weight=2.0`. `Stabber` (default `DEFAULT_DIRS=13` jittered Fibonacci directions, clamped `MIN_DIRS=3`..`MAX_DIRS=26`) + `disambiguate_sdf(...)` patch only ambiguous-band cells, parallel over z-slices, leaving unresolved votes (majority grazing/suspect) to the winding number; `cells_flipped` is computed from the SIGNED slice's previous sign (not the unsigned distance, which is always `>= 0`, so the counter used to count inside votes instead of flips). Python API: `raystab_points(verts, tris, points, n_dirs=None, seed=0, parity=False, escape_weight=2.0) -> (inside, inside_votes, outside_votes, escape_votes)`, `raystab_grid(...) -> (inside, score, info)`, and an opt-in `raystab=` keyword on `sdf_grid`/`morph_close` (`raystab_dirs`/`raystab_seed`/`raystab_parity`); kwargs are APPENDED after `surface` so Graft's positional call keeps working. It is OFF by default and byte-identical to the winding-only path; `info['raystab']`/`report['raystab']` is only set when on. `sutura_engine/cast.py` wraps both functions and `graft.py` exposes `shell_wrap(..., raystab=..., raystab_dirs=..., raystab_seed=..., raystab_parity=...)` plus the `SUTURA_RAYSTAB` env opt-in (feature-detected so an older extension degrades to off). CLI/GUI wiring is deliberately DEFERRED until a real-world-corpus measurement (see `docs/cli-gui-parity-notes.md`). Regression: the `raycast`/`winding` Rust unit tests and `tests/test_raystab.py`.

- **Phase B indirect-predicates self-intersection repair is implemented but experimental.** `rust/sutura-geom` now contains the full B1–B5 chain (indirect predicates, exact triangle–triangle classifier, projected 2D CDT, `arrangement_lite` Python binding, `--experimental-indirect-autorefine` wiring). The "constrained edge blocks segment insertion" panic on dense multi-segment host triangles was fixed in commit `fe33fe6` by computing the planar arrangement of all segments before constraint enforcement. The prototype passes 38 Rust unit tests and 9 Python smoke tests. It is **disabled by default** and is not yet a replacement for `--experimental-autorefine` because the exact-rational-only subdivision does not finish in practical time on dense self-intersection scans (e.g. thingi10k_1038441). Phase C1 (0.4.0) added crossings built from original input data and a rigorous interval filter in front of the exact predicates (results unchanged by construction; differential-tested); thingi10k_1038441 now completes (~463 s on an M2, previously did not finish in 30+ min). Phase C2 removed the linear scans from the per-host constrained triangulation (walking point location, vertex–triangle incidence, segment-corridor walk, local chord update, BigInt exact fallback) with byte-identical output (order-independent digest via `examples/arrangement_digest.rs`; `--features cdt-check` asserts every accelerated query against the linear reference scan): the full thingi10k_1038441 mesh went from 830 s to 52.5 s on the same x86_64 VM (29.8 s on the M2). Phase C3 (exact-zero shortcut for an LPI tested against its own edge, interval rejection in points_are_equal, per-host frame cache, integer-arithmetic point3d/line_line_intersection/sort key) keeps the digest and brings the VM time to 28.1 s; Phase C4 (`point::RatKey` — hashing/comparing reduced `(numer, denom)` directly instead of `num-rational`'s continued-fraction `Hash`, valid only because every crate rational stays reduced — for the weld map and the per-host `(s,t)` index, plus integer `Point3::to_rational` over one common power-of-two scale) keeps the digest and brings it to 17.6 s. It stays disabled by default (see `rust/sutura-geom/README.md`). Profiling: `cargo run --release --example bench_arrangement --features profile -- <mesh.obj>` (macOS: set `DYLD_LIBRARY_PATH` to the Python env's `lib`, and do not launch it through `nohup`, which strips `DYLD_*` under SIP).

## Rust core performance work (`rust/sutura-geom`)

- **Output-identity rule:** a performance change to the exact arrangement keeps the output identical, not merely equal in face count. Verification is the order-independent digest of `examples/arrangement_digest.rs` (exact rational vertex coordinates + winding; independent of triangle order, vertex numbering and cyclic rotation), compared before/after on thingi10k_1038441, its subsets (produced by `examples/bench_arrangement.rs`) and at least thingi10k_1038439, 55772, 502009, 46012 and artec_metal-nut. `cargo test --release --features cdt-check` additionally asserts every accelerated triangulation query against the linear reference scan; CI runs the Rust tests with and without that feature.
- **Output-changing work is a separate decision:** changes that alter the output (for example Sloan-style queue flipping instead of the Steiner split used for non-convex quadrilaterals) are not performance work. They require an explicit decision and a measurement on the real-world corpus, and are never bundled with an identity-preserving optimisation.
- **Reference input and digest:** the OBJ is converted from `tests/real-world-samples/thingi10k_1038441.stl` with trimesh (5.x; its vertex welding is why the subsets differ slightly from the C1 table in the crate README). The reference digest for the full mesh, identical across C1–C4, is `7b05a6fc3b785f42` (37,323 output faces, 4,445 proper SI pairs). Corpus/test OBJs go to `/tmp`, never into the repo.
- **Measurement (Linux):** `cd rust/sutura-geom && cargo run --release --example arrangement_digest -- /tmp/<mesh>.obj [...]` prints time, face counts and digest per file; `cargo run --release --example bench_arrangement --features profile -- /tmp/<mesh>.obj` gives the per-phase split.
- **Measurement (macOS, conda env `sutura-env`):** build with `PYO3_PYTHON=/opt/homebrew/Caskroom/miniforge/base/envs/sutura-env/bin/python cargo build --release --example arrangement_digest`, then run `DYLD_LIBRARY_PATH=/opt/homebrew/Caskroom/miniforge/base/envs/sutura-env/lib ./target/release/examples/arrangement_digest /tmp/thingi10k_1038441.obj`. `DYLD_LIBRARY_PATH` must not be exported while cargo itself runs (libiconv conflict), and without `PYO3_PYTHON` the example links against a different libpython than the one on `DYLD_LIBRARY_PATH`.
- **Evaluated CDT variants (developer switches, NOT the default):** `cdt2d::experimental` holds per-thread bits (thread-local, so parallel unit tests cannot interfere): 1 = keep constraint flags on `flip` (the default `flip` rebuilds with `Tri::new` and clears the outer-edge flags on the flipped side), 2 = Sloan queue flips instead of split vertices on the constraint, 4 = propagate segment endpoints lying inside a host edge to every triangle sharing that edge (`arrangement::collect_edge_points`; zero-area triangles are kept unchanged). Set them with `SUTURA_CDT_OPTS` (`arrangement_digest`), `sutura_geom._set_cdt_experimental(bits)` or `benchmark_repair_corpus.py --cdt-experimental BITS`. Findings: the reference output has T-junctions exactly where an endpoint lies inside a host edge (bit 4 removes them: 100045 56 -> 0 odd-use edges; regression `propagated_edge_points_remove_t_junctions`), Sloan cuts 1038441 from 37,323 to 32,481 faces and 17.8 s to 13.8 s (regression `sloan_flips_add_no_vertex`), bit 1 has no effect once Sloan is on. End to end on the 40 real-world samples (`--experimental-indirect-autorefine --no-fallback-ftetwild`) strict watertight stays 31/40 for all variants and for the pipeline without the tier; propagation costs ~35 % arrangement time. Default output therefore unchanged; results table in the crate README. Enabling one by default is an output-changing decision (see the rule above).
- **Timing status, thingi10k_1038441 full mesh:** C1 (v0.4.0) 462.7 s on the Apple M2 / 830 s on the x86_64 VM (2 vCPU); C2 29.8 s / 52.5 s; C3 16.8 s / 28.1 s; C4 10.6 s / 17.6 s. Timings are compared only within one machine. Remaining cost on the VM after C4 (profile build): per-host triangulation 7.4 s, classification 4.6 s, implicit point construction 2.3 s, weld and output 0.06 s (the phases overlap in the profile). On the 90k-face meshes (46012, artec_metal-nut) C4 gains only 1–3 %; their cost lies outside these phases and has not been profiled yet.
